# RFC-0012: Testing, Quality, Governance, and Open Source

- **Status:** Accepted

## Decision

Setu follows a testing pyramid: focused unit tests, integration tests for infrastructure boundaries, and end-to-end tests for key user paths. Coverage targets are 95%+ for routing and security, 90%+ for providers and APIs, and 85%+ for the dashboard, while prioritizing meaningful tests over vanity metrics.

Pull requests must pass format, lint, type, test, API/plugin compatibility, security, dependency, and documentation checks. Use Conventional Commits, semantic versioning, small predictable releases, and feature branches from `main` for public collaboration.

Major architecture changes require RFCs; smaller durable choices use ADRs. Governance begins founder-led, expands to core maintainers, then may adopt a technical steering committee. Documentation, responsible disclosure, public roadmap, contributor onboarding, and civil code review are part of the product.
